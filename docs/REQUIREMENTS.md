# Requirements

## 1. Functional Requirements

### 1.1 User Authentication & Authorization

| ID | Requirement | Priority |
|---|---|---|
| FR-01 | Users shall be able to register with email and password | Must Have |
| FR-02 | Users shall be able to log in and receive a JWT token | Must Have |
| FR-03 | JWT tokens shall expire after a configurable period and support refresh | Must Have |
| FR-04 | Protected endpoints shall require valid JWT authentication | Must Have |
| FR-05 | Passwords shall be hashed using BCrypt before storage | Must Have |

---

### 1.2 Dashboard

| ID | Requirement | Priority |
|---|---|---|
| FR-06 | Dashboard shall display market overview (major indices summary) | Must Have |
| FR-07 | Dashboard shall display the user's portfolio summary (total value, daily change) | Must Have |
| FR-08 | Dashboard shall show top gainers and losers from the S&P 500 | Should Have |
| FR-09 | Dashboard shall display a data freshness indicator (last pipeline run timestamp) | Must Have |
| FR-10 | Dashboard shall show recent watchlist activity | Should Have |

---

### 1.3 Stock Search & Listing

| ID | Requirement | Priority |
|---|---|---|
| FR-11 | Users shall be able to search stocks by ticker symbol or company name | Must Have |
| FR-12 | Search shall return results with ticker, name, sector, and current price | Must Have |
| FR-13 | Stock listing shall support pagination | Must Have |
| FR-14 | Stock listing shall support sorting by name, price, market cap, and score | Should Have |

---

### 1.4 Stock Detail Page

| ID | Requirement | Priority |
|---|---|---|
| FR-15 | Stock detail shall display current price with daily change (amount and percentage) | Must Have |
| FR-16 | Stock detail shall show an interactive price chart (1W, 1M, 3M, 6M, 1Y, 5Y) | Must Have |
| FR-17 | Stock detail shall display key fundamental metrics (P/E, P/B, ROE, EPS, Market Cap, etc.) | Must Have |
| FR-18 | Stock detail shall show the EquiMind Score (0–100) with sub-score breakdown | Must Have |
| FR-19 | Sub-scores shall include Profitability, Growth, and Valuation with individual values | Must Have |
| FR-20 | Stock detail shall display technical indicators (RSI, MACD, Bollinger Bands, MAs) | Must Have |
| FR-21 | Stock detail shall show the AI-generated summary with source attribution | Must Have |
| FR-22 | Stock detail shall display the data freshness date for all data points | Must Have |
| FR-23 | Users shall be able to add/remove stocks to watchlist from the detail page | Must Have |

---

### 1.5 EquiMind Score

| ID | Requirement | Priority |
|---|---|---|
| FR-24 | The scoring engine shall compute a composite score from 0 to 100 | Must Have |
| FR-25 | The score shall comprise weighted sub-scores: Profitability, Growth, Valuation | Must Have |
| FR-26 | Each sub-score shall be independently visible (not just the composite) | Must Have |
| FR-27 | If a metric is unavailable, it shall be excluded with a note (e.g., "Based on 8 of 9 metrics") | Must Have |
| FR-28 | The score shall include a textual explanation (e.g., "Strong profitability, demanding valuation") | Should Have |

---

### 1.6 Technical Analysis

| ID | Requirement | Priority |
|---|---|---|
| FR-29 | The system shall calculate and display RSI (14-period) | Must Have |
| FR-30 | The system shall calculate and display MACD (12, 26, 9) with signal line | Must Have |
| FR-31 | The system shall calculate and display Bollinger Bands (20-period, ±2 std dev) | Must Have |
| FR-32 | The system shall calculate and display Moving Averages (50-day, 200-day SMA) | Must Have |
| FR-33 | Technical indicators shall be rendered as interactive overlay charts | Should Have |

---

### 1.7 AI Summaries

| FR-35 | AI output shall be structured as JSON (summary, bull_case, risk_factors, sentiment, sentiment_reason) | Must Have |

| FR-37 | AI summaries shall be labeled as "AI-generated — not investment advice" | Must Have |

## 2. Non-Functional Requirements

### 2.1 Performance

| ID | Requirement | Target |
|---|---|---|
| NFR-01 | API response time for stock detail | < 500ms (95th percentile) |
| NFR-02 | API response time for search | < 300ms (95th percentile) |
| NFR-03 | Dashboard page load time | < 2 seconds |
| NFR-04 | Screener query execution time | < 1 second for any filter combination |
| NFR-05 | Data pipeline completion time | < 30 minutes for full S&P 500 universe |

---

### 2.2 Security

| ID | Requirement |
|---|---|
| NFR-06 | All passwords shall be hashed with BCrypt (minimum 10 rounds) |
| NFR-07 | JWT tokens shall use RS256 or HS256 with a strong secret |
| NFR-08 | API endpoints shall validate and sanitize all input parameters |
| NFR-09 | SQL injection shall be prevented via parameterized queries (JPA) |
| NFR-10 | CORS shall be configured to allow only the frontend origin |

---

### 2.3 Reliability

| ID | Requirement |
|---|---|
| NFR-11 | The system shall gracefully handle missing data (no crashes, clear UI indicators) |
| NFR-12 | The data pipeline shall retry failed API calls up to 3 times with exponential backoff |
| NFR-13 | The system shall function in demo mode when external APIs are unavailable |
| NFR-14 | Database transactions shall maintain ACID compliance |

---

### 2.4 Scalability

| ID | Requirement |
|---|---|
| NFR-15 | The database schema shall support the full S&P 500 universe (~503 stocks) |
| NFR-16 | The system shall store at least 5 years of historical daily price data per stock |
| NFR-17 | The architecture shall allow future extension to additional stock universes |

---

### 2.5 Usability

| ID | Requirement |
|---|---|
| NFR-18 | The UI shall be responsive (functional on desktop and tablet viewports) |
| NFR-19 | Charts shall be interactive (hover tooltips, zoom, time range selection) |
| NFR-20 | Data freshness shall be visible on every page showing market data |
| NFR-21 | Error states shall display user-friendly messages (not stack traces) |
| NFR-22 | AI-generated content shall be clearly labeled as such |

---

### 2.6 Deployability

| ID | Requirement |
|---|---|
| NFR-23 | The entire system shall be deployable via a single `docker-compose up` command |
| NFR-24 | Environment configuration shall use `.env` files (not hardcoded values) |
| NFR-25 | The system shall provide a health check endpoint (`/api/health`) |

---

### 2.7 Maintainability

| ID | Requirement |
|---|---|
| NFR-26 | Backend code shall follow Spring Boot best practices (layered architecture) |
| NFR-27 | Frontend code shall use component-based architecture with React |
| NFR-28 | The data pipeline shall be modular (separate modules for ingestion, validation, computation) |
| NFR-29 | All API endpoints shall be documented (Swagger / OpenAPI) |

---

## 4. Constraints

| Constraint | Description |
|---|---|
| **Data Source** | Limited to Yahoo Finance free API (rate limits, data availability) |
| **Stock Universe** | S&P 500 only (~503 stocks) |
| **AI Model** | Local LLM only (no cloud API calls) |
| **Budget** | Zero monetary cost (open-source tools and free data only) |
| **Timeline** | Single semester (~16 weeks) |
| **Team Size** | Solo developer |
| **Deployment** | Single-machine deployment via Docker Compose |

---

## 5. Acceptance Criteria

The project shall be considered complete when:

1. ✅ A user can register, log in, and access the dashboard.
2. ✅ The dashboard displays market overview with data freshness indicator.
3. ✅ A user can search for any S&P 500 stock and view its detail page.
4. ✅ The stock detail page shows price chart, fundamentals, EquiMind Score with sub-score breakdown, technical indicators, and AI summary.
5. ✅ The screener filters stocks by at least 3 criteria with sortable results.
6. ✅ Watchlist and portfolio features persist data across sessions.
7. ✅ The data pipeline runs successfully and populates the database.
8. ✅ Demo mode functions without any external API calls.
9. ✅ The entire system starts via `docker-compose up`.
10. ✅ Project documentation is complete (README, problem statement, literature survey, timeline, requirements).
